# 后台分项验证与启用边界（2026-11-04）

后续检查点：本分项控制源码已随579d8b48头像/界面版部署14函数，后台和调度仍关闭。现已使用指定任务隔离执行器完成非空CSV/XLSX真实验收46项；不是云Worker或调度验收。下文“未部署”为方案初次编写时状态，详见[续验证据](./followup-progress-20261104.md)。

本轮新增本地分项选择能力；未部署、未开启云端后台或调度。`JOBS_ENABLED=true`不再足以运行businessJobs，还须在服务端明确配置`BUSINESS_JOB_STAGES`。空配置返回`business_stages_disabled`；未知、重复或空项在数据库访问前拒绝。调度来源验证继续执行，事件参数不能选择作业。AI Worker不使用此配置，真实模型继续暂缓。

配置为英文逗号分隔的下列精确名称，无`all`或通配符；执行顺序固定为表中顺序。结果按分项返回，失败保留已完成分项结果并停止后续分项；失败不撤销已提交业务，重试须依赖原任务租约及幂等凭证。结果只包含已有作业计数和错误码，不返回原始SDK错误。

| 分项 | 效果 | 独立真实验收条件 |
|---|---|---|
| knowledge | 发布生成的API知识版本 | 版本/hash及超管可见性；不顺带跑其他作业 |
| claims | 释放已过48小时的待确认接取 | 原claim/需求版本一致、名单计数正确；不影响后续接取；不自动确认 |
| demands | 关闭已到接取截止的待接取需求 | 只变更pending_claim且无有效claim；公开列表隐藏；在途需求不变 |
| completions | 创建7天待验收提醒outbox | 按当前成果ID去重；只提醒、不自动验收；校园管理员范围正确 |
| inbox | outbox转换为站内通知 | 崩溃恢复、重复5次不重复通知或计数；file.delete不被误消费 |
| exports | 生成待处理导出 | 私有存储前置、CSV/XLSX实际内容/下载/当前权限；初次仍优先指定任务隔离执行器 |
| expire_exports | 将过期导出解绑 | 先核对24小时实际到期、holds及引用；此项有数据库写入，与只读到期拒绝不同 |
| retention | 数据保留清理 | 新鲜备份、原始保留起算点、删除标记及holds对账；不得用空队列代替非空清理验收 |
| file_deletions | 实体文件删除 | 所有绑定和保留护栏、删除租约、失败重试、恢复边界；明确对象清单后单独验证 |
| orphan_copies | 孤儿副本清理 | 复制登记和结果不明对象复核；人工待核查任务不得自动删除；不等同临时上传目录清理 |
| subscriptions | 微信订阅发送 | 真实模板/字段、本人点击授权、成功和失败反馈；不确定结果不得盲目补发 |

建议从仅`inbox`的非删除项开始，在实际测试数据及恢复边界明确后逐项验收；未完成某分项不得把其他分项的通过结果挪作证明。当前Worker历史配置为3秒且无触发器，后续启用前须重新读取实际配置、调整足够的运行预算并验证超时/租约；本轮没有改配置。

本地预览选择不会连接云端：

```powershell
$env:BUSINESS_JOB_STAGES = 'inbox'
npm run jobs:dry-run
Remove-Item Env:BUSINESS_JOB_STAGES
```

`scripts/run-business-jobs.mjs --apply`也必须明确选择分项。它是运维写入入口，配置选择不是写入或删除授权，不能用该入口替代当前指定导出任务的隔离执行器。初次真实执行前要核验测试目标、当前数据、备份和预期影响。

本地新增7项测试覆盖空/错误配置、选择前验证、禁止连带删除、失败结果、单独站内通知的幂等性、单独需求到期以及错误分项零写入；均为内存适配器，不能替代云端租约、事务或调度验证。代码见`server/maintenance/business-stages.ts`、`server/jobs-entry.ts`、`server/maintenance/business-jobs.ts`及`tests/unit/business-job-stages.spec.ts`。
