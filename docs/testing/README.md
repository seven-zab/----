本轮验收反馈的修复、复测命令与范围见[修复记录](./qa-fixes-20261026.md)。原acceptance-20261026.csv保留为首轮执行记录，不由开发脚本覆盖。

## 提测前置与分工

开发负责人提交：代码版本/工作区差异指纹、契约source_hash、构建版本、部署函数清单、已实现范围、已知问题、数据备份及恢复证据。体验版只有实际上传后才能填写版本号和二维码；当前尚未上传。未完成的功能记“未实现”，不能记成测试通过。

测试负责人维护[用例模板](./acceptance-template.csv)的执行副本。模板由`node scripts/generate-acceptance.mjs`从冻结规格所有验收表生成；`--check`核对完整性。重新生成只更新模板，测试人员应将实际结果保存在另一文件中，不把实测结果填入模板后又覆盖。结果取“通过/失败/阻塞/未实现/未执行”，每项附证据；不把本地内存适配器测试填成真实云通过。

建议两名测试人员分别负责主流程与权限异常，再相互复测缺陷。并发测试由开发和测试共同执行；测试必须观察真实云端最终数据、事件、计数和审计，不能只看Toast。日志仅保存请求编号、资源ID、脱敏错误分类，不传播手机号、认证材料或密钥。

## 账号与数据准备

准备多个真实微信账号：超管、村A管理员、村B管理员、村A农商户发布者、村B发布者、SZTU师生服务方、团队成员及未参与队员。一个账号可测试多身份切换，但不能代替跨用户隔离测试。项目方指定账号作为超管/测试账号；迁移核对和受控初始化前不能仅靠旧permission字段认定v2已授权。

所有新增需求标题加`QA-日期-批次-用例号`，团队使用同样标记，记录新增ID。不要编辑/删除原历史业务作为测试素材；不清库、不重建集合，不调用旧initAdmin/initDatabase。村A/村B使用经核验的真实区域映射；不能把本地fixture“测试村A”灌入历史业务替代真实村。无法确认映射时将依赖的云用例标阻塞。

## 第一轮：发布、审核与个人闭环

1. 游客查看已审核乡村/校园需求；构造发布请求被拒绝；不能查看待审正文、手机号或精确地址。对应AUTH-01、AUTH-02、DEM-02、AUTH-09。
2. 农商户提交乡村需求，检查原三问卷板块和无人机分类；SZTU师生提交校园需求。未知选填留空，预算未知不变成0，默认截止不晚于已知开始时间。对应FORM-01、DEM-01。
3. 村A管理员只能审村A乡村需求；村B越权请求失败，校园只超管审核。管理员在范围内可显式自审需求，但不能自审身份。对应AUTH-03、AUTH-04、AUTH-10、AUTH-12。
4. 审核通过后公开；服务方接取后为claiming。此时进度、电话、精确地址请求均拒绝。发布者确认后才processing，对接人才可读取对方电话。对应FLOW-04、CONTACT-01。
5. 服务方写进度，状态仍processing；有文字且无图片可交成果进入pending_review。发布者能查看成果文字，退回必须有原因，再提交保留历史。只有owner验收通过才completed。对应DEM-06、FLOW-03、FLOW-05。
6. 重复点击、超时重试使用同一幂等键；同键改内容拒绝。真实核对只建一单/一次成果，不以客户端提示作为证据。

## 第二轮：团队与名单交接

授权代发另测DELEGATE-01：受益人在个人页复制自己的代发识别码给有范围权限的管理者；管理者在“本次代发授权”发起本次草稿，受益人核对/补齐内容和本人附件后确认。管理者按已确认快照提交待审；重复消费同一授权只关联一单。检查实际owner仍为受益人，代发操作者不能代其确认接取或验收；未确认、撤销、篡改hash和跨范围均拒绝。授权确认与需求审核是两个独立动作。

在个人页进入“我的团队与邀请”，服务方建队，按对方分享的识别码邀请；邀请接受前对方不能作为成员接取。个人页分享的是识别码，不是登录凭证。

在需求详情选择“选择团队接取”，明确选择本单参与者并包含负责人。用10名长期队员、3名本单成员验证：只给3名实际成员任务权限，普通队员无地址/电话/进度权限；成员可记进度，仅本单负责人可交最终成果。对应TEAM-01至TEAM-05。

本单负责人提出名单/负责人交接，发布者查看新名单和拟负责人后同意才生效。批准前旧名单继续有效；批准后被换出成员立刻失去必要私有访问和操作权，新成员按新绑定授权履约。原名单记录保留，活动任务计数准确；重复/迟到审批不能覆盖当前版本。长期团队负责人交接需要接任者本人接受，不自动替换任何任务负责人。对应STAT-04、DATA-01、TEAM-05。

## 第三轮：权限、到期、并发和作业

- 用直接接口调用测试，不仅点击页面：伪造grant_id/owner_id/内部标记、跨村、非参与者、撤权和封禁均应服务端拒绝。身份到期不能建立新关系，原已确认任务可按原绑定授权继续；换设备后再测。对应AUTH-05、AUTH-14、AUTH-15。
- 200个并发接取验证最终只占用一个主体；确认/取消、复审/旧审核、撤权/敏感写分别并发。记录每个请求结果及最终主记录、事件、outbox；本地串行内存测试不证明云事务行为。
- 在隔离的QA新增记录或可控服务端时钟中测试48小时/7天/30天边界。48小时未确认释放，旧claim作业不能释放新claim；7天只提醒不自动验收；任务结束30天服务方电话/地址关闭，不能等待清理执行才拒绝访问。
- 维护作业必须由授权运维入口执行；客户端internal=true不能触发。当前本地维护入口为`node scripts/run-business-jobs.mjs`，默认dry-run；`--apply`才连接已确认测试环境，需安全提供SDK运维凭据。开发者工具登录不等于这个Node进程获得运维凭据。
- 重复执行作业、租约后恢复、重复消费事件，检查站内通知不重复。本人标已读不影响他人通知；混入他人通知ID时整笔拒绝。微信订阅失败不回滚业务；订阅发送尚未接通时明确标未实现/待验收。对应EVT-01、EVT-02、NOTICE-02。

## 最终完整验收

授权代发已有本地实现，仍待真实云验证。其余能力补齐并部署后再执行并判定：完整私聊、统计CSV/真实XLSX、政策轮播管理、知识库、AI四类写操作/每日10次额度、文件文档扫描与清理、分批迁移及恢复。AI必须用真实模型记录provider/model/SDK、超时/鉴权/部分成功证据；项目方暂缓模型配置时相关用例保持待执行，不能删掉或以fake替代。

全部规格用例以模板为准，包含Q51—Q57补充项。重点统计fixture、跨月/午夜/空分母、历史参与人数、文件多绑定和holds、90/180/365天保留、导出24小时过期均需单独证据。正式生产迁移、部署、平台审核和发布不在测试授权中。

验收阻断项包括：越权读取/写入、错误开始或完成任务、重复占用/重复执行、数据损坏、契约/类型/构建失败及未处置的交付安全问题。测试报告必须同时给出总用例数、通过/失败/阻塞/未实现/未执行数量、缺陷及复测记录、体验版版本号、已知风险和签字结论。缺少真实证据时结论为“未完成完整2.0验收”。
