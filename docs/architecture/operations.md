# 运行规则、配置与真实环境交付

版本：2.0（已确认冻结）；2026-10-25；Q51—Q57及Q58整体理解均已确认。本文与README.md、contracts.md共同组成正式开发规格，不表示能力已实现。

## 1. 时间轴不是需求推荐

首版无独立推荐系统、推荐API、匹配分数或推荐理由。需求广场仅普通筛选与排序。接取后时间轴由demand_events生成，事件追加写、可见性过滤，不让客户端提交任意目标status。

| 当前阶段 | 操作者与按钮 | 结果 |
|---|---|---|
| 待接取pending_claim | 合资格个人/团队负责人：接取 | claiming，等待需求方确认，48小时占用 |
| 待确认claiming | 需求方：同意/拒绝；服务方负责人：撤回 | 同意才processing；拒绝/撤回/超时释放占用，按截止时间恢复待接取或结束为expired |
| 服务中processing | 个人接取者/本单实际参与者：记录到场、阶段进度 | 主状态仍processing，追加进度事件；不强制照片或定位 |
| 服务中processing | 个人接取者/本单负责人：提交成果 | pending_review；文字总结必填，附件选填 |
| 待验收pending_review | 需求方：验收通过/退回补充 | completed或processing；退回理由必填，保留各次成果 |
| 服务中/待验收 | 双方负责人：申请/答复终止 | 同意才terminated；争议走有权管理员处理 |

页面根据服务端返回的allowed_actions显示按钮。allowed_actions为提示，执行请求仍须事务重查；不提供setStatus/updateStatus通用写接口。时间轴阶段顺序固定，进度事件可多次追加，不把到场等每个节点扩展为生命周期状态。未确认不能提前开始，未验收不能由服务方直接点完成。服务方按钮与AI使用同一领域动作。

## 2. 身份期限与在途任务

师生grant有效期自审核通过起365天；到期申请复核，保留原grant及任务绑定，新审核生成新版本/授权。农商户和村委grant默认不设自然到期，人工撤销仍立即生效。超级管理员不因此自动获得免审的自授身份路径。

授权判定必须区分三条路径：

1. 新发布、提交新审核、修改后复审、新接取、确认开始服务、新建队/邀请/新确认参与等建立新关系的动作：账号active且相应grant当前有效。自然到期者先复核，不能借在途例外将尚未确认的claim转成processing。
2. 记录进度、提交成果、验收/退回、协商终止及查看必要履约信息：允许资源原绑定grant自然到期的用户完成既有已确认关系，不能借此新发布或新接单。仍校验账号active、原grant从未被人工撤销、本单owner/负责人/实际参与关系与状态；不能用另一个无关过期grant代替。自然到期者不能被加进新名单。本人撤回未确认claim/取消尚未开始的需求属于释放义务，可按资源归属执行，但不能增加新权限。
3. 人工撤权、封禁：不走自然到期例外。封禁阻止业务访问和操作；撤权阻止该授权覆盖的操作，不自动删除本人其他有效身份。管理员通过独立有审计的交接/争议用例解决在途任务，不能冒充原用户签字或自动验收。

首次接取/确认时记录claim、owner及参与者使用的grant_id与角色快照，authorizations保留expiry/revocation事实。鉴权实现命名建议assertCanStartNewAction与assertCanContinueBoundTask，不能用一个“grant过期全部拒绝”的中间件覆盖两种行为。读历史仍执行资源关系与数据期限检查。

## 3. 数据保留与清理

期限是平台首版产品策略，不宣称替代适用的外部要求。全部按服务端UTC时间戳计算；每日清理任务带游标和幂等记录，展示日期使用Asia/Shanghai。1天=24小时，1年=365天。

| 数据 | 起算点与期限 | 到期行为 |
|---|---|---|
| 电话/精确地址对服务方的开放 | 当前claim确认后开放，任务completed/cancelled/expired/terminated的ended_at后30天截止 | 到期getContact/getServiceLocation拒绝服务方；换出名单/负责人交接立即重新判定，不延用30天权限；需求方仍可管理本人资料 |
| AI会话消息 | 每条created_at后90天 | 删除原文、检索上下文和私有引用；用户deleteSession可提前删除，立即停止展示及新调用 |
| 需求私聊 | 每条created_at后180天 | 删除正文及附件绑定；会话摘要可保留需求关联和不可读的过期提示，不向接任者移交历史 |
| 身份材料附件 | 每次审核reviewed_at后180天 | 删除该次材料绑定；保留审核结论、角色、范围、审核者、时间、理由摘要，不留材料正文副本 |
| 业务过程/成果附件及审核操作记录 | 任务结束/申请审核结束后至少365天；未结束持续保留 | 清理到期附件；审核记录只可按明确清理流程归档脱敏，不允许前端改写。项目基础记录、状态变更元数据和脱敏统计继续保留 |
| 导出文件 | 生成成功后24小时 | getDownloadUrl拒绝，定时删除私有文件；需要时重新生成，不能靠旧临时链接延长期限 |

期限检查在读接口执行，不能只依赖定时任务及时删除。临时下载URL有效期取平台支持上限与剩余业务访问期限的较小值；供应商不支持该上限时采用服务端下载代理，不生成可能越过业务期限的链接。涉及期限或私有信息的文件不设置公开读，不假定隐藏按钮能收回已经签发的链接；公开政策配图不因此禁止正常公开展示。

文件清理以file_bindings为单位：一份文件可能绑定原单、复制的新单或争议证据，仍有有效绑定就不能删除实体。安全检查、共享绑定计数与删除租约应防止“刚绑定即被后台删掉”的竞争；外部存储删除可重试，不在数据库事务内执行。

业务私有联系人快照在任务结束365天后清理为工程默认；这不删除用户个人资料中的本人联系方式，也不延长服务方30天访问期。待审身份申请尚无reviewed_at时不按已审核期限误删，可由本人撤回，撤回后按审核结束同类策略清理。

争议/安全事件需由有权管理员设置data_holds（scope、reason、created_by、created_at、review_at、released_at），对必要证据暂缓物理清理；到期复查，解除后恢复原期限，不能永久无限顺延。保留证据不扩大普通用户可见性，查看留审计。AI删除只删除对话及未执行意图，不撤销已提交需求；保留脱敏执行凭证、资源ID及幂等结果，不能因删除会话再次执行写操作。

需纳入清理的存储面包括主库、文件、检索片段、导出、运行日志与备份。应用日志默认30天且不写电话/完整event/证明正文；滚动备份默认30天，恢复后先执行删除标记与holds对账，再开放访问，避免删除数据复活。脱敏删除凭证不保存原始敏感内容。

## 4. 通知与统计

站内通知是持久化事实，不意味着用户一定看见：业务事务写outbox，消费者幂等生成notifications，失败重试并可排障。微信订阅消息仅在授权、模板及平台条件满足时尽力发送；无短信/邮件，拒绝订阅不阻断业务。外部发送结果不确定不能通过重做业务补救。

48小时未确认释放、待验收7天提醒继续有效，均不得自动确认或自动验收。定时任务与用户动作检查同一资源版本，旧提醒不能影响新一轮claim或成果。

统计采用首次提交批次cohort；待审、驳回、取消、终止分别可见，草稿排除；同ID修改不增数，复制新ID另计。已解决仅已验收completed；解决率=同批已解决/同批提交量，分母0返回null。期间完成量以completed_at另计。已确认参与人数取该批项目所有曾生效名单按user_id去重，包含换出成员，不代表所有人均完成；团队总成员和未确认接取者不计。CSV/XLSX复用相同范围、筛选和算法版本；村委只导出有权村域，不因能审师生身份就获得校园统计权限。

## 5. 工程初值与配置约束

以下是执行AI可直接落地的工程初值，必须服务端校验并集中配置。业务已确认的10次/日、48小时、7天、365天复核和数据期限不允许被客户端修改。修改这些业务参数须同步规格与验收。

| 配置 | 默认 |
|---|---|
| 标题/描述/进度总结 | 标题4—80字符；描述10—5000；进度1—2000；成果总结1—5000；trim后计Unicode码点，与contracts.md一致 |
| 图片与普通文档 | 图片最多5张，每张5MB；普通文档最多3份，每份10MB；图片jpeg/png/webp，文档pdf/docx/xlsx；身份材料仅图片/pdf |
| 团队/本单参与者 | 最多20人，包含负责人；所有实际参与者都须确认加入且资格匹配；需验证数据库事务限制，不得拆成部分成功的名单确认 |
| 分页 | 默认20，上限50；稳定cursor，包含排序时间及_id |
| AI写意图 | 30分钟；会话一运行任务，轮询2—5秒，60秒后提示稍后查看 |
| AI模型请求 | 单请求超时30秒、输出上限2048 tokens；每个逻辑模型请求最多3次总尝试（首次+至多2次瞬时失败重试），SDK不另叠加重试，Worker重领不重置计数；权限/校验错误不重试，已成功工具不再执行 |
| 防刷 | 每用户AI父消息每分钟10条；写命令每分钟30条；另设环境模型预算熔断，返回RATE_LIMITED/MODEL_UNAVAILABLE，不伪装成无关问答10次额度耗尽 |
| 幂等与任务租约 | 幂等响应7天；后台租约120秒并按需续租，超时领取前检查旧执行结果 |
| 统计与导出 | 快照目标5分钟内；单次导出最多366天、5000行，超限要求缩小范围，不静默截断；文件24小时有效 |
| 大字版 | 基准字号、行高与间距倍率1.3，覆盖全部页面 |

这些限制作为Schema源统一生成前后端规则；上传后服务端核验真实类型，不只看文件扩展名。具体模型/SDK需查官方能力、在测试云环境实测并锁版本，不能凭文档初值断言平台一定支持。若事务容量不支持20人完整确认，实施AI须改进模型与锁设计满足一致性，无法满足再报告明确约束，不能静默减少业务能力。

## 6. 迁移及交付门槛

迁移前备份并验证恢复，先dry-run输出逐集合数量、映射、异常清单和预计变化，再分批幂等执行与对账。未知身份、辖区、审核或验收证据不能猜测；隔离保留原记录供人工处理，不直接授予管理权、不自动批准旧需求、不清空重建。测试种子只写隔离测试环境，禁止自动对生产运行。

完整开发交付包括：源码与锁文件、严格Schema与生成工具、数据库规则/索引/迁移、单元/集成/页面及真实端到端测试、可恢复部署步骤、监控与回滚说明、真实模型测试证据及可体验小程序版本。现有类型错误必须修复，npm run typecheck不得以跳过文件、禁用strict或批量any掩盖；lint须零错误，警告有清单。全部构建和关键测试实际通过后记录证据。

真实测试云环境至少验证：身份审核→普通表单/AI提交→村委或超管审批→公开→个人/团队接取→发布者确认→进度→成果→退回再提交→验收→统计与双格式导出；另测游客、跨村、校园隔离、自接、管理员自审、超额混合消息、自然到期及封禁。模型必须真实调用，微信订阅消息需记录真实权限条件及成功/失败反馈，mock不替代真实验收。

由项目方通过安全配置提供小程序AppID、独立测试云环境及部署授权、可用模型权限/配额、订阅模板、经核验的初始化超级管理员映射和测试身份。代码仓库与聊天不保存密钥、真实证明或生产备份。缺少外部资源时，执行AI继续完成不受影响的代码与本地验证，报告具体阻塞及所需资源，保持“待真实验收”，不能宣称全部完成。

体验版构建/上传需使用项目方既有账号与授权；正式生产数据迁移、部署、提交平台审核及正式发布另行确认，不属于本轮文档编辑或自动测试授权。不擅自采购资源。基础身份初始化脚本一次性审计、运行后禁用，不能残留硬编码管理员后门。
